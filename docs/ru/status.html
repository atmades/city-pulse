Работа идёт вертикальными срезами, один pull request на шаг. В Sprint 1 репозиторий становится платформой: источники подключаются конфигурацией, а не кодом.

  1. ГотовоSprint 0: фундамент, релиз v0.1.0CI как обязательный шлюз для merge, сканирование секретов, защищённая ветка main, Terraform для слоёв BigQuery и service accounts, ADR-001 и ADR-007.
  2. ГотовоМодель спецификации источника #6Модель источника на Pydantic; правила вроде «нельзя включить источник до проверки лицензии» записаны в коде. ADR-008.
  3. ГотовоPoller для загрузки данных #7Повторы с растущей паузой, идемпотентное хранение сырых данных, JSON-логи, корректное завершение. Первый живой источник: статус станций Citi Bike.
  4. ГотовоСправочник и журнал на GitHub PagesЭтот сайт: архитектура, конфигурация, концепции и журнал по сессиям, раздаётся из папки docs/.
  5. СледующееDocker-образМногоэтапная сборка, запуск не от root, один образ работает локально, в CI и в Kubernetes.
  6. В планахKubernetes в kind, деплой из GitHub ActionsDeployment с настройками безопасности и корректным завершением; smoke-тест ждёт первый сохранённый снимок. ADR-010.
  7. В планахАрхив сырых данных в AWS и S3-адаптерЗащищённый S3-бакет и IAM-роль только на добавление в Terraform; S3Store реализует порт хранилища. ADR-009.
  8. В планахGitOps с Argo CDКластер сам забирает желаемое состояние из репозитория, вместо того чтобы CI его туда отправлял.
  9. В планахОстаток тикета #5Контракты данных, публикация в Pub/Sub, метрика доступности источника, фид метро (A/C/E).
